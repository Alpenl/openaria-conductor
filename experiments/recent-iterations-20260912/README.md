# 最近十次迭代的消融实验

日期：2026-09-12。基线：`24bb5089c60997dcfb75f9043af4a020c0b6374e`。
范围：主线最近十次合入/直接提交，2026-08-30 至 2026-09-11。
候选分支：`refactor/recent-iterations-ablation-20260912`。

本轮落地三项简化：删除重复维护的目录校验状态和模式开关；按需验证时直接定位
会话；时间戳摘要直接计算、CSV 逐行输出。三个生产文件合计净减少 40 行。
没有增加生产依赖、配置开关或新的通用框架。

## 实验与决定

### A：去掉待校验集合和组合开关——保留

PR #67 后生产调用只剩两个模式：列出元数据、验证指定会话。原来的
`revalidate_pending`、`verify_payload`、`session_ids` 三个参数仍可表达很多没有调用者的组合。
`_pending_session_verification` 又重复记录了“有摘要、没有校验快照”的状态，
在发现、失效、封存、删除等路径共有 13 处引用。

候选用一个 `verify_session: str | None` 表达实际使用的两个模式，删除整个待校验集合，
把正常延后、录制忙碌及校验被中断时的结果统一投影为没有当前校验结论的摘要。
校验通过/内容损坏的快照，以及用于下载的已验证 manifest 摘要仍分别保留。

单独应用状态删减时，原有 79 项协调器测试通过。隔离性能组恢复目录扫描，
中位数为 15.39 ms，基线为 14.53 ms，文件访问工作量相同。这项的收益是减少
状态同步点和无调用者的模式组合；**不据此声称性能提升**。

### B：去掉单会话访问的全目录遍历——保留

基线虽然只对目标会话做完整校验，但先 `iterdir()` 全部会话，再逐个 `is_dir()`
并筛选名字。候选直接在已准入的当前/历史根目录下检查目标路径。
普通列表仍执行完整发现；定向查询不会清除其他会话的缓存。

新增边界检查阻止绝对路径、上级路径、空名字、尾斜线和 NUL 字符进入定向路径。
既有无符号链接读取、文件身份检查、内容校验和录制期间的中断机制继续执行。

测试卷包含一个由现有测试录制器封存的有效会话和 2000 个其他目录。
其他目录不含有效会话负载，这个实验隔离的是目标访问之前的目录遍历成本，
并不模拟 2001 段真实视频的校验耗时。

| 指标，每次访问 | 基线 | 仅 A | A+B |
| --- | ---: | ---: | ---: |
| 枚举目录条目 | 2001 | 2001 | 0 |
| 候选目录 `is_dir()` 调用 | 2001 | 2001 | 1 |
| 会话级完整内容校验调用 | 1 | 1 | 1 |
| 中位耗时 | 14.53 ms | 15.39 ms | 3.35 ms |
| 额外 Python 峰值分配 | 332027 B | 331817 B | 91510 B |

三组返回的视频字节摘要一致。新增回归分别覆盖当前/历史根目录、完整返回字节、
保留其他会话列表，以及非法会话路径；不只是断言某个内部方法被调用。

### C：去掉时间戳报告的整表中间对象——保留

PR #66 的普通录制和标定时间戳功能，都先构造整份逐帧行对象，再做摘要或写 CSV。
标定行还包含左眼、右眼、最近 IMU 三层对象。只需要统计最近 IMU 偏差时，
这些对象没有用途；写文件也不需要把所有行同时保留。

候选直接从时间轴计算摘要，CSV 按行迭代输出，并用标准库 `bisect_left` 替换
两个手写二分查找循环。保留公开的 `build_frame_timestamp_rows()` 元组返回接口，
让确实需要整表的调用者仍可显式构造。未新建通用时间轴框架，也未合并两个读取入口。

输入为 18000 视频帧和 240000 IMU 样本，相当于 30 fps / 400 条记录每秒的十分钟
合成时间轴。固定源数据在测量前创建；普通录制入口的验证与读取被替换为这份固定输入，
测量报告/导出层，包括包分组、时间估计、摘要及 CSV 写出，不含视频哈希或磁盘输入读取。

| 操作 | 基线中位耗时 | 候选中位耗时 | 基线额外峰值 | 候选额外峰值 |
| --- | ---: | ---: | ---: | ---: |
| 普通录制摘要 | 256.90 ms | 214.25 ms | 29.46 MiB | 20.38 MiB |
| 普通录制 CSV | 336.44 ms | 310.84 ms | 29.46 MiB | 20.38 MiB |
| 标定时间戳摘要 | 83.62 ms | 7.61 ms | 18.32 MiB | 0.74 MiB |
| 标定时间戳 CSV | 187.22 ms | 161.93 ms | 17.73 MiB | 0.15 MiB |

所有摘要及 CSV 文件 SHA-256 与基线一致。额外执行 20000 次最近样本匹配，覆盖
单样本、重复时间、精确命中、等距取前、边界外和大数值单调时钟，输出索引摘要一致，
并逐项核对选中距离确实最小。

### 负对照：去掉会话级内容校验——拒绝

仅在实验进程里把完整验证替换为 manifest 检查，然后破坏右眼文件、请求左眼文件。
完整实现拒绝访问；消融后左眼仍可读，新增完整性回归按预期失败，且不是环境异常。
所以不能把会话完整校验视为“单文件读取已有哈希”的重复工作。

这个负对照只改变实验进程中的函数，不写入生产实现，也不修改真实录制。
故障注入结果及完整断言日志保存在 `results.json` 的 `negative_control` 中。

## 其余最近改动的审查结论

下面为源码与既有回归审查；未对每一项做硬件消融，不将“保留”冒充新的实机证据。

| 改动来源 | 决定与理由 |
| --- | --- |
| #59/#60/#61/#65/#67 历史目录与回放 | 落地 A/B。启动不做全盘哈希、列表仅元数据、访问时精确校验和中断控制仍有独立职责。 |
| #66 普通录制/标定时间戳导出 | 落地 C。两个读取入口不合并：标定入口限定 calibration、split-eyes，拒绝依赖音频；普通报告支持生产会话，两者接受域和时间重建约束不同。 |
| #63 网关流生命周期 | 保留取消信号、流容量与退出回收。现有预览/SSE/TLS、1000 次断开重连和服务退出测试在全量回归中通过。 |
| #64 Python/Rust 资源收拢 | 保留 CaptureEngine / SessionStore 所有权边界；采集资源和会话资源寿命不同。没有重新暴露被收拢的细粒度 Rust 对象。 |
| #65 音频连续性、时钟和 IMU 修复 | 保留有界写入队列、终止时 drain/join、原始时钟证据和完整 IMU 包去重。主机微基准不足以证明真实 USB/磁盘延迟下可以移除这些处理。 |
| #65 画质配置与会话 v3 | 保留编码参数与来源契约。删除 H.265、码控或编码身份属于功能减少，不是等价抽象消融。 |
| #65/#66 远程删除 | 保留完整预检查、续录依赖、幂等结果与下载/录制互斥，既有故障回归通过。 |
| #65/#66 安装、Wi-Fi、HTTP 与回退 | 保留下载/固件安装 umask 边界、当前 Wi-Fi 继承、失败才启用救援热点，以及升级/回退的一致访问策略；没有引入新的部署编排层。 |
| a9e60e1 离线包 SHA256SUMS | 保留：校验范围包括 installer、运行时和依赖，不能由应用 wheel 身份替代。 |
| #61/#62/#66/#67 Echo 资源更新 | Conductor 托管固定构建资源；本轮没有把生成的 JavaScript 当作应用源码修改。 |

## 复现

使用已具备本项目 `.venv` 和可用 `src/rp_ylx/_native.abi3.so` 的相同主机环境。
准备一个不存在的临时基线目录，固定到实验基线；原生扩展复制到基线以统一执行路径：

```bash
shnote --what "建立实验基线副本" --why "保留原始实现供对照" run git clone --shared . /tmp/openaria-ablation-baseline
shnote --what "固定实验基线" --why "复现最近十次迭代后的源码" run git -C /tmp/openaria-ablation-baseline checkout --detach 24bb5089c60997dcfb75f9043af4a020c0b6374e
shnote --what "统一原生扩展" --why "排除执行路径差异" run cp src/rp_ylx/_native.abi3.so /tmp/openaria-ablation-baseline/src/rp_ylx/_native.abi3.so
shnote --what "运行消融对照" --why "核对行为、文件访问与内存成本" run .venv/bin/python experiments/recent-iterations-20260912/run_ablation.py --baseline /tmp/openaria-ablation-baseline --output /tmp/openaria-ablation-rerun.json
shnote --what "运行项目检查" --why "验证候选完整行为" run .venv/bin/python scripts/check.py
```

每组先预热一次，随后 7 次计时取中位数，再单独用 `tracemalloc` 测一次额外 Python
峰值分配；结果摘要计算在计时/内存测量之外。文件访问计数也单独测量，避免插桩
改变时间结果。A 独立性能组只在实验进程中恢复扫描，生产代码没有实验开关。
正式结果来自本轮测试进程结束后的复测。

主机为 Linux x86_64，具体平台与 Python 版本已记录。内存数字不是整个进程 RSS，
不包括测量前已构造的输入或 Rust 分配。耗时受主机负载影响；本轮没有部署 RDK、
做真实媒体长录或声称提升硬件帧率，目录操作次数和输出一致性是更稳定的结论。
