# 0.2.1 录制格式与时钟

生产默认档位为 `efficient`：双眼各 HEVC Main、CBR 12288 kbps、8 bit
YUV420、QP 18–32、GOP 30、无 B 帧。传感器请求 60 fps，每两帧保存一帧，
保存标称 30 fps；实际帧率以帧索引中的单调时间为准。`recording.preset=high`
保留 H.264 16384 kbps，`standard` 保留 H.264 8192 kbps。

相机默认在每次打开采集前设置标准 UVC 自动曝光（`auto`），读取控件确认，
让画面适应实际光照。`camera.exposure_time_absolute` 可显式设为 1–100
（单位 100 µs）启用短曝光；设为 `null` 时保留操作者的硬件曝光配置。
控制失败或回读不一致时不会宣称配置成功。10 ms 在明亮场景通过帧率实验，
但现场发现固定 10 ms 在室内会明显欠曝，因此不作为默认。该相机没有暴露
自动曝光最大时长/帧率优先控件，自动曝光暗场可能降低源帧率；应依据实际
帧时间审计判断，不能保证弱光下同时实现足够亮度和 60 fps 源采集。

新的正式封存会话使用 `ylx.device-session.v4`，继续读取 v1/v2/v3。
采集中仍写原始 NDJSON/WAV，以保留分段恢复能力。停止采集后：

1. 帧索引和 IMU 使用 Zstandard level 1，每 1 MiB 独立、带校验和的压缩帧。
2. WAV 转 FLAC，逐字节验证解码后的 S16LE PCM，保存 PCM SHA-256。
3. 比较压缩前后原始文件摘要；校验压缩 artifact 的摘要、大小和文件身份。
4. 原子封存新清单后清理原始副本。中断或磁盘写入失败时保留原始恢复日志。

`artifact.bytes/sha256/artifact_id` 始终描述可按 Range 下载的实际文件。
`storage_encoding` 描述还原编码、原始字节数与摘要。`audio.wav` 角色标识原始
PCM 流，实际存储格式由 `media_type=audio/flac` 和 `.flac` 路径声明；音频的
采样域、原始 WAV 头大小及 ALSA 时钟证据不因无损压缩而改变。

`ylx.frame-index.v2` 保留 v1 字段，并新增 `timestamp_audit`：V4L2 原始 flags、
驱动单调时间来源、DQBUF 主机时间、经过 YLX AVI1 APP0 结构验证的 BE24
相机计数器。驱动序号与相机计数器分别保留，不能假设二者的缺口一一对应。

会话 `capture_audit` 汇总实际帧率、P50/P95/P99/最大间隔、源缺口、计数器
匹配和回绕/重置、IMU 实际交付槽位频率、读取时间窗、boot_id 与时钟能力。
百分位使用有界的 100 µs 桶，超过 1 秒的溢出桶保守报告最大值。

MP4 分段仍采用编码器的标称帧率时基。**定量分析和完整视频导出必须使用
`frames.host_monotonic_ns`**。配套 Bridge SDK 支持压缩索引，导出逐帧 VFR
时间戳，并沿用 ALSA 捕获时钟校正音频速率；不可用 `frame/30` 替代真实时间。
浏览器 HEVC 解码能力取决于浏览器和系统，文件下载不受影响。

v4 需要配套 Bridge SDK 源码提交
[`5bb7031426da6ab280d1bd4eefa7d42de26991ea`](https://github.com/Alpenl/openaria-bridge-sdk/commit/5bb7031426da6ab280d1bd4eefa7d42de26991ea)
或包含该提交的更新构建。旧 `v0.4.3` 发布包不支持 v4；不可仅根据同名包版本
判断兼容性。安装该固定源码版本后，按 SDK 原有 verify / export 流程消费。

IMU 的两个六轴槽位共享一次 USB 读取的中点时间。现有协议没有经过确认的
独立 ADC 时间戳、FIFO 溢出计数、轴/尺度及完整标定参数，软件不会插值冒充
高频独立采样，也不会把计数器匹配当成物理同步标定。UVC PTS/SCR 与曝光帧
关联尚未验证，不用它们覆盖帧时间；不施加实验中观测到的约 -14 ms 读取差。
相机—IMU 空间标定、长期噪声和有真值 VIO 漂移仍需相应实测数据。

固件公开版本限定在 0.2.x，首次公开交付为 0.2.1。网页检查同时比较版本与
提交身份，以便本地同版本候选升级到公共正式构建；旧版本渠道不提供降级。
OSS 发布仍拒绝覆盖已公开版本的不同产物，后续变更必须递增补丁号。
