## 2. Real-Hardware Issues Discovered & Fixed During Acceptance

1. **Hobot SDK VBR Parameter Struct Mismatch (`csrc/miro-ego-encoder/`)**
   - **Finding**: On real RDK X5 headers (`/usr/include/hb_media_codec.h`), `mc_h264_vbr_params_t` and `mc_h265_vbr_params_t` expose only `intra_period`, `intra_qp`, `frame_rate`, and `qp_map_enable` (no `bit_rate`, `max_bit_rate`, `initial_rc_qp`, `vbv_buf_size`, `min_qp_*`, `max_qp_*`).
   - **Fix**: Updated `SET_VBR` in `csrc/miro-ego-encoder/miro_ego_stereo_pipeline.c`, aligned `mc_rate_control_vbr_t` in `csrc/miro-ego-encoder/tests/stubs/hb_media_codec.h` and `csrc/miro-ego-encoder/tests/test_pipeline_e2e.c`, then compiled cleanly against real `/usr/hobot/lib/libmultimedia.so.1` + `libhbmem.so.1`.
2. **`imu_open_failed: Operation not permitted (os error 1)` (`deploy/miro-ego/miro-ego.service`)**
   - **Finding**: `ProtectClock=yes` on systemd 249 (Ubuntu 22.04 / RDK X5) implicitly attaches `DevicePolicy=auto` + `DeviceAllow=char-rtc r`, causing `open("/dev/video0", ...)` (and `/dev/ion`, `/dev/vpu`, `/dev/jpu`, `/dev/snd/*`) inside `miro-ego.service` to fail with `EPERM` despite `SupplementaryGroups=audio video vpu jpu vps misc` (verified directly with `systemd-run`).
   - **Fix**: Set `ProtectClock=no` in `deploy/miro-ego/miro-ego.service` with explanatory comment (`CapabilityBoundingSet=` already drops `CAP_SYS_TIME`).
3. **`board_model: null` / `is_rdk_x5: false` in `miro-ego probe` & `status` (`crates/miro-ego-hw/src/thermal.rs`)**
   - **Finding**: `/proc/device-tree` is a symlink to `/sys/firmware/devicetree/base`, which `read_bounded_bytes` rejects (`O_NOFOLLOW` / ancestor symlink guard).
   - **Fix**: Changed `DEFAULT_BOARD_MODEL_PATH` to `"/sys/firmware/devicetree/base/model"`. Post-fix `miro-ego probe` and `miro-ego status` report `"board_model": "D-Robotics RDK X5 V1.0"` and `"is_rdk_x5": true`.
4. **Calibration Contract (`camera.effective_fps` & Per-Sample IMU Interval in `spectacular`)**
   - **Finding A**: `crates/miro-ego-cli/src/runtime/native_capture.rs` previously exported `effective_fps = frames_written / duration_seconds`, which dropped to `29.3428` (`> 20,000 ppm` below `30.0`) on an ~8s run due to ~156ms start/stop wall-clock overhead even with 0 dropped frames. Fixed to export configured nominal `self.effective_fps` (`30.0`), matching `recovery.rs` and `mock_capture.rs`.
   - **Finding B**: `miro-ego` `0.3.0` stamps intra-packet IMU sample `0` at `packet_midpoint - sample_period` (~2.5ms before `host_read_start_ns`) and sample `1` at `packet_midpoint` within `[host_read_start_ns, host_read_end_ns]`, whereas `tools/miro_ego_host/spectacular/adapter.py` and `timebase.py` expected identical packet timestamps on both samples. Updated `adapter.py` and `timebase.py` to validate intra-packet ordering (`sample_0 <= sample_1`), validate `sample_1` within `[host_read_start_ns, host_read_end_ns]`, allow up to `50 ms` pre-interval interpolation offset for `sample_0`, fit the packet clock on `packet[-1]`, and added unit test coverage in `tools/miro_ego_host/tests/test_spectacular.py`.
