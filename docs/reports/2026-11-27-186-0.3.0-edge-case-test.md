## 1. Confirmed Bug Discovered During Investigation

### [P1] NetworkManager Wi-Fi Powersave Config Silent Override (`wifi.powersave=3` remains active)
- **Root Cause**: On Ubuntu 22.04 / RDK OS 3.5.0, `/etc/NetworkManager/conf.d/default-wifi-powersave-on.conf` (`wifi.powersave = 3`) is installed by default. Miro-Ego installs [`deploy/miro-ego/90-miro-ego-wifi-powersave.conf`](file:///home/alpen/DEV/openaria-conductor/deploy/miro-ego/90-miro-ego-wifi-powersave.conf) (`wifi.powersave = 2`) via [`crates/miro-ego-deploy/src/manager.rs`](file:///home/alpen/DEV/openaria-conductor/crates/miro-ego-deploy/src/manager.rs#L216-L220). Because `'d' > '9'` in ASCII lexicographic order, `default-wifi-powersave-on.conf` loads **after** `90-miro-ego-wifi-powersave.conf` and silently wins.
- **Direct Board Evidence**:
  - `NetworkManager --print-config` output:
    ```text
    # (etc: 10-globally-managed-devices.conf, 90-miro-ego-wifi-powersave.conf, default-wifi-powersave-on.conf)
    [connection]
    wifi.powersave=3
    ```
  - `iw dev wlan0 get power_save` reported `Power save: on`.
  - `/sys/module/aic8800_fdrv/parameters/` showed `ps_on=N`, `dpsm=N`, **`ap_uapsd_on=Y`**.
  - [`crates/miro-ego-network/src/nmcli.rs`](file:///home/alpen/DEV/openaria-conductor/crates/miro-ego-network/src/nmcli.rs) `ProfileSpec::Hotspot` / `ProfileSpec::WifiClient` also do not write per-profile `powersave=2` into `[wifi]` sections.
- **Impact**: Explains why `iw dev wlan0 get power_save` stayed `on` while running the rescue AP `MiroEgo-5B8C4012`, contributing to AP client drop risk (`aicwf_sdio` `Del sta` mismatch observed earlier).
- **Recommended Fix**: Rename drop-in to `zz-miro-ego-wifi-powersave.conf` (removing legacy `90-miro-ego-wifi-powersave.conf` cleanly on upgrade), consider `ap_uapsd_on=0` in `aic8800-miro-ego.conf` if supported by module, and optionally emit `powersave=2` in managed NM `[wifi]` profiles.
