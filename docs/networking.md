# Open Aria 网络连接与救援指南

本指南说明如何从电脑或手机进入 Open Aria 管理页面、在 Wi-Fi 和设备热点之间切换，以及在
网络配置失败后重新连接设备。

## 最重要的固定信息

设备切换到热点模式后，管理地址固定为：

```text
10.42.0.1
```

常用入口如下：

| 用途 | 固定值 |
| --- | --- |
| 热点名称 | `OpenAria-XXXXXXXX`，后缀因设备而异 |
| 热点密码 | `12345678` |
| Web 管理页面 | `http://10.42.0.1:8080/` |
| SSH 登录 | `ssh OpenAria@10.42.0.1` |
| SSH 密码 | `123456` |

热点网关在设备配置中固定为 `10.42.0.1/24`。浏览器地址只填写 `10.42.0.1`，不要把
`/24` 写进网址。

## 不同连接方式的地址规则

| 设备模式 | 设备地址 | 推荐打开方式 |
| --- | --- | --- |
| 设备热点 | 固定为 `10.42.0.1` | `http://10.42.0.1:8080/` |
| Wi-Fi 客户端 | 通常由路由器动态分配 | `http://rp-ylx.local:8080/` |
| 有线网络 | 由部署配置决定，可为 DHCP 或静态地址 | `http://rp-ylx.local:8080/` 或实际 IP |

只有热点地址是产品固定地址。设备加入其他 Wi-Fi 后，`10.42.0.1` 不再是该连接的访问地址。
局域网 IP 可能在重启或切换路由器后变化，因此优先使用 `rp-ylx.local`。

`rp-ylx.local` 依赖电脑或手机的 mDNS 支持。如果它无法解析，应查看路由器的 DHCP 客户端
列表、当前页面的“网络详情”，或者重新进入设备热点。

## 1. 通过设备热点进入后台

1. 在电脑或手机的 Wi-Fi 列表中找到 `OpenAria-XXXXXXXX`。
2. 输入热点密码 `12345678`。
3. 如果系统提示“此网络无互联网”，选择仍然保持连接。
4. 等待设备给电脑或手机分配 `10.42.0.x` 地址。
5. 在浏览器地址栏输入 `http://10.42.0.1:8080/`。

每台设备的 `XXXXXXXX` 后缀不同，但同一台设备的热点名称保持不变。现场有多台设备时，应按
设备标签或事先记录的后缀进行区分。

热点模式也可能支持 `http://rp-ylx.local:8080/`，但固定 IP 不依赖名称解析，通常更可靠。

## 2. 通过现有局域网进入后台

电脑或手机与设备连接到同一个局域网后，打开：

```text
http://rp-ylx.local:8080/
```

如果打不开：

1. 确认控制设备与 Open Aria 位于同一个局域网，而不是访客隔离网络；
2. 从路由器的 DHCP 客户端列表中查找设备地址；
3. 使用 `http://<设备局域网IP>:8080/` 直接访问；
4. 暂时关闭 VPN 或会代理内网流量的软件；
5. 仍然无法找到设备时，连接它的救援热点。

## 3. 从 Web 切换到新的 Wi-Fi

网络设置入口位于页面顶部当前连接方式的位置。它通常显示为 `Wi-Fi`、`设备热点` 或
`有线`。

1. 确保当前没有录制任务。录制期间不能修改网络。
2. 点击页面顶部的当前连接方式，打开“网络设置”。
3. 页面会自动扫描一次附近 Wi-Fi，也可以点击刷新图标重新扫描。
4. 选择目标 Wi-Fi。隐藏网络可以使用“手动添加网络”。
5. 按需输入 Wi-Fi 密码，然后点击“连接”。
6. 在“切换到……”确认框中点击“确认切换”。

确认后，当前页面可能立即失去连接，这是正常现象。接下来：

1. 让电脑或手机也连接到刚才选择的 Wi-Fi；
2. 打开 `http://rp-ylx.local:8080/`；
3. 如果名称无法解析，从路由器中查找设备获得的新 IP；
4. 使用 `http://<新IP>:8080/` 访问。

目标 Wi-Fi 密码错误、无法获得 DHCP 地址或默认路由不可用时，设备会尝试恢复上一次已验证的
连接。无法恢复时，它会回到 `OpenAria-XXXXXXXX` 救援热点。

## 4. 从 Web 切换到设备热点

1. 确保当前没有录制任务。
2. 点击页面顶部的当前连接方式，打开“网络设置”。
3. 点击“启用设备热点”。
4. 在确认框中点击“确认切换”。
5. 原页面断开后，在电脑或手机上连接 `OpenAria-XXXXXXXX`，密码为 `12345678`。
6. 打开 `http://10.42.0.1:8080/`。

Wi-Fi 客户端和设备热点共用 `wlan0`。设备进入热点模式后，原来的无线局域网地址通常不再
可用；不要继续刷新旧地址。

## 5. 从热点切回 Wi-Fi

1. 保持电脑或手机连接设备热点。
2. 打开 `http://10.42.0.1:8080/`。
3. 点击页面顶部的“设备热点”。
4. 选择目标 Wi-Fi，输入密码并确认切换。
5. 页面断开后，让电脑或手机加入同一个目标 Wi-Fi。
6. 使用 `http://rp-ylx.local:8080/` 或设备的新局域网 IP 重新进入。

切换完成后，`10.42.0.1` 不再能从目标 Wi-Fi 访问。这个地址只属于设备热点网段。

## 6. 忘记已保存的 Wi-Fi

“忘记 Wi-Fi”会删除设备保存的 Wi-Fi 连接，并让设备回到救援热点。

1. 打开“网络设置”。
2. 点击“忘记 Wi-Fi”。
3. 在“忘记已保存的 Wi-Fi”确认框中点击“确认忘记”。
4. 当前页面断开后，连接 `OpenAria-XXXXXXXX`。
5. 打开 `http://10.42.0.1:8080/`。

只有确实不再使用原 Wi-Fi 时才执行该操作。

## 7. 通过 SSH 维护设备

热点模式下：

```bash
ssh OpenAria@10.42.0.1
```

局域网模式下：

```bash
ssh OpenAria@rp-ylx.local
```

SSH 密码为：

```text
123456
```

需要执行管理员命令时使用 `sudo`，密码仍为 `123456`。账号名称区分大小写。

用于只读排查的常见命令：

```bash
ip -4 address
nmcli device status
systemctl --no-pager --full status rp-ylx.service
systemctl --no-pager --full status rp-ylx-network-control.service
journalctl -u rp-ylx-network-control.service --since=-15min -o cat
```

不要直接删除或手工改写 `/etc/NetworkManager/system-connections` 中的受管连接。通过 Web
执行切换，设备才能保留验证和失败回退状态。

## 8. 故障排查

### 找不到 `OpenAria-XXXXXXXX` 热点

- 等待设备完成启动和网络恢复流程，然后重新扫描 Wi-Fi；
- 确认搜索的是 `OpenAria-` 开头的名称，不是旧名称；
- 设备可能已经成功加入已保存的 Wi-Fi，此时热点不会同时出现；
- 有线网络可用时，先通过有线地址或 `rp-ylx.local` 查看“网络详情”；
- 不要在录制期间强制重启设备，先确认设备是否仍在录制。

### 已连接热点，但 Web 页面打不开

- 确认设备地址是 `10.42.0.1`，不是电脑或手机自身的地址；
- 确认完整网址为 `http://10.42.0.1:8080/`；
- 确认系统没有因为“无互联网”自动离开设备热点；
- 暂时关闭 VPN、HTTP 代理和移动数据自动切换；
- 检查电脑或手机获得的地址是否属于 `10.42.0.0/24`；
- 可以先测试 `ping 10.42.0.1`，再重新打开浏览器。

### 切换 Wi-Fi 后设备消失

先让电脑或手机加入目标 Wi-Fi，再尝试 `rp-ylx.local:8080`。如果目标 Wi-Fi 配置失败，等待
设备完成回退，然后重新扫描 `OpenAria-XXXXXXXX`。不要反复切换电脑网络，以免错过救援
热点出现。

### `rp-ylx.local` 无法打开

这通常是名称解析或网络隔离问题，不代表设备服务已经停止。改用实际 IP；热点模式直接使用
`10.42.0.1`，局域网模式从路由器 DHCP 列表中查找设备地址。

### 页面显示“网络修改未启用”或按钮不可用

录制期间、网络控制器不可用、设备正在恢复网络或维护窗口关闭时，页面会禁止网络修改。先结束
录制并等待当前操作完成，然后刷新状态。如果仍然不可用，通过 SSH 查看网络控制服务状态和
最近日志。

### 页面显示“相机未接入”

相机状态不影响 Web、网络或 SSH。它只会禁止预览相关操作和开始录制，不需要通过切换网络来
处理相机问题。

## 9. 固定凭据的使用范围

设备热点和 SSH 使用固定公共凭据，适用于受信任的内部网络。不要把路由器的 `8080` 或
`22` 端口转发到公网，也不要把设备直接接入不受信任的公共网络。
