# 0.2.16 — 录制失败收尾自动恢复

录制失败收尾或最终状态写入遇到临时 I/O 错误后，后台每两秒尝试继续收尾。
重试绑定原会话，已完成的媒体恢复不会因状态提交失败而重复执行；仍在写入的线程
保留资源所有权，直到排空并完成状态提交才允许下一条录制。正常停止后的状态提交失败
也会自动重试。失败录像及其已保存连续前段保留。

音频失败不会提前跳过视频排空，已完成的视频分段仍会登记用于恢复；失败诊断在
原生音频线程结束后采样，保留收尾期间新出现的错误。

新增只读 `GET /api/v4/capture/readiness`（权限 `getCaptureReadiness`），返回当前
存储余量、是否可开始及原因。Echo Web 每两秒刷新，将历史失败结果与当前准入条件区分。
接口为 v4 的可选增量，旧固件返回 404 时网页沿用原有能力检查。

系统状态盘保留 256 MiB / 1024 inode，用于状态持久化，即使录像使用独立 exFAT 分区
也检查。录像卷和旧 loop 镜像宿主盘的既有阈值保留。录制期间触及系统盘余量会触发收尾。

针对现场发现的约 19 秒写入停顿和 142 秒音频检查点停顿，压缩视频队列每眼上限
提高到 64 MiB / 32 秒帧数，音频 PCM 队列约 32.8 秒，待提交音频上限 48 段
（默认 5 秒分段约 240 秒）。队列仍有界，保留 fsync、连续前段校验与失败保护。
这些缓冲不能消除持续磁盘故障，也不代表已经确定 SD 卡或 loop 的物理故障原因。

验证覆盖数据库提交失败后自动恢复、收尾异常重试、活跃写入线程互斥、分盘系统空间不足、
视频积压排空、音频提交积压边界、音频失败时视频尾段收尾及手机/桌面准入提示。
硬件无关回归通过后发布；本版本未将现场相机升级或作为真实 SD 卡长录验收。
