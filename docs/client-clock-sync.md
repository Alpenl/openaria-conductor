# 从连接的手机或电脑校准设备日期

RTC 未保持日期、离线启动的 RDK 可能从 2000 年开始计时。新版 Echo / Web
在手机或电脑打开控制页面后，使用浏览器所在设备的日期初始化 RDK 系统时间。
整个流程只需要手机/电脑能访问 RDK，不要求 RDK 能访问互联网。

- 连接后且设备空闲时自动尝试；页面保持打开时，每 30 秒检查一次，设备服务
  的 authority epoch 改变时立即重新检查。录制按钮提交开始命令前也先确认校时。
- 已被 NTP 同步的时间优先。接受一次客户端时间后保留该时间参考，防止多台
  手机反复修改时间；同一次设备开机内，服务重启会读取持久校时记录并检查时间连续性；系统重启、记录损坏或时间跳变后重新校时。
- 正在录制或收尾时不调整日历时间；录制期间新连接的页面会在设备恢复空闲后
  重试。单调时钟、帧时间和音视频同步算法保持原有计时方式。
- 支持此功能的固件若校时失败，页面仍可连接和查看，但开始新录制时会重试，
  失败则提示错误，不提交开始录制命令。旧固件对新接口返回 404 时兼容原行为。

## 接口与权限

`GET /api/v4/clock`（权限 `getDeviceClock`）返回 `ylx.clock-status.v1`：
`source` 为 `ntp`、`client` 或 `unsynchronized`。未同步时提供 `challenge`。
它绑定调用者，只能使用一次，并按设备的单调时钟在 5 秒后过期。

`POST /api/v4/clock/sync`（权限 `syncDeviceClock`）沿用现有 Bearer、Origin
和 CSRF 策略，请求例如：

```json
{
  "schema": "ylx.clock-sync-request.v1",
  "challenge": "0123456789abcdef0123456789abcdef",
  "unix_time_ms": 1789524000000
}
```

时间必须在发送前从客户端读取（浏览器为 `Date.now()`），有效范围为
2024-01-01（包含）到 2100-01-01（不包含），单位是 UTC Unix 毫秒。
挑战值必须使用刚收到的实际值，不能复用示例。该接口不使用 Idempotency-Key，
重复或超时请求应重新 GET；409 表示正在录制、挑战过期或设备时间已变化。
浏览器不使用超过 2 秒才返回的挑战响应，整个尝试最多等待 5 秒。

设备 HTTP 服务仍以普通用户运行。现有 root 控制器通过受限 Unix socket
接收严格校验过的校时操作，并用 `clock_settime_ns(CLOCK_REALTIME, ...)`
调整系统时间。只有该控制器的 systemd unit 获得 `CAP_SYS_TIME`，无需赋予
网页服务 root 权限。特权进程在实际调整时还必须取得录制使用的跨进程锁，
因此排队请求即使在客户端超时后执行，也不能穿过录制保护。

## 使用范围

这解决的是“哪一天、几点”的录制日期。它信任手机或电脑自身的日期正确，
不提供传感器间的高精度同步，网络传输仍带来小量时间偏差。
本机制不为 RTC 增加断电供电；断电后需要至少一个客户端再次打开控制页面。
已有录制的历史日期不会被批量改写。

交付需要同时安装新版 Conductor、随包固定的 Echo / Web 构建产物，以及
更新后的 `rp-ylx-network-control.service`。只复制网页或 Python 文件不足以
授予必要的系统时钟权限，应使用正常的离线固件安装/升级流程。

## 2026-11：开机校时规则

网页显示完整设备时间（按浏览器本地时区显示）、来源和最近校时日期。设备与本机日期相差超过60秒时明确提示，
不自动覆盖已经接受的时间。空闲时可选择“使用这台手机时间重新校准”，再次确认后才执行；正在使用NTP时不允许覆盖。
每次自动校时包含实际系统时间回读、浏览器再次GET验证；浏览器回读与手机相差超过2秒则报错。
只连接Wi-Fi不会触发校时，必须打开网页；无需互联网。手机自身日期必须正确。

校时记录保存在特权网络状态目录clock.json（0600），包含boot ID、单调时钟与UTC参考。
服务重启不会丢失有效记录，设备重启不得沿用旧boot ID的记录。状态不导入工厂配置备份。
所有开始录制入口统一在服务端检查校时状态，持有录制/校时共用锁后才能分配会话ID。
未校时拒绝开始并提示“请打开手机页面校准时间”；首次通过手机校时可播报“设备就绪”。
提示音遵循现有启用/静音/音量设置，播放失败不影响校时或录制。

GET /api/v4/clock/check为v2扩展状态，始终提供短时挑战；同步POST沿用/clock/sync，
新请求schema为ylx.clock-sync-request.v2，增加布尔replace，仅显式确认才传true。
旧GET /clock和v1自动校时请求保持兼容。NTP或另一客户端先完成校时后，自动请求保留已有时间；
旧挑战不得用于覆盖新校准结果。所有修改仍受真实录制flock保护，包含保存阶段。

新录像在clock-calibration.json附件中保存calibration（source、boot_id、synchronized_at_ms、age_seconds）、开始日期和utc_offset_seconds。
附件通过已有manifest.logs记录校验和并随录像导出；断电恢复保留原来源。清单schema与capture.json计划字段保持旧版兼容，旧录像无需补写。
已校时新录像以开始日期加单调时长计算结束日期，不因外部时间跳变改写开始日期；历史素材不批量修改。
这不是多设备高精度对时，也不保证手机日期本身正确。
