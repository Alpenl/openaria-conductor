# 工厂一键刷机与离线自动恢复（验收候选）

入口 `scripts/factory_recovery/recover.py`，Python 3.10+，Windows/Linux/macOS 共用。
目前 Linux 快速写卡和原板首次启动已经实测。首启安装权限及长录音频缓冲问题已修复；
修复后的完整镜像尚未再次刷卡，Windows/macOS写卡与实际断电恢复仍待验收。

## 推荐流程

1. 原系统尚能启动时，菜单 **1 备份配置**。设备须空闲，备份为密码加密的 `.oar`，保存在电脑。
2. 电脑安装 `python -m pip install -r requirements.txt`，菜单 **0** 下载并校验官方 RDK X5 3.5.0 镜像。
   工具包自带 `bundle.tar` 与 `firmware.json` 时会自动选取离线录制软件。
3. 插入目标卡，以管理员身份运行工具，选 **5 一键刷机**。选择卡、加密配置备份及新镜像保存位置，
   输入备份密码。工具生成包含系统、离线软件和设备专用配置的镜像，再快速写卡并完整回读校验。
   写入前仍需输入 `ERASE <目标整盘路径>`，不会自动选择内部系统盘。
4. Verified 后安全拔卡，放回**原来的地瓜派**，接通稳定电源。首次启动会扩容系统文件系统、初始化录像分区、恢复配置、离线安装
   录制软件、恢复提示音量及系统播放音量，并自动重启一次。无需先接网线、手动配置Wi-Fi或在线下载软件。
5. 等待恢复完成后访问设备网页，检查网络、身份、音量和录像列表为空，再做短录/停止/播放验收。

Windows 用管理员终端运行 `start.cmd`；Linux/macOS 使用安装好依赖的Python执行
`sudo /path/to/python recover.py`。`start.command` 提供终端入口；Unix管理员权限需自行授予。
准备镜像与软件包阶段可以联网；卡装回设备后的恢复不依赖网络。

磁盘空间：保留约10.4GB官方镜像、约10.4GB生成镜像及2.77GB下载缓存。生成镜像内包含设备专用
配置，不上传公共位置；生成镜像不覆盖已有文件。每次需要使用新的输出文件名。

## 自动恢复命令

```text
python recover.py auto-flash --disk <整盘> --image <官方.img> --sha256 <官方镜像SHA256> --bundle <bundle.tar> --bundle-sha256 <软件包SHA256> --profile <配置.oar> --output <新的恢复.img>
```

备份密码交互输入，不放命令行。`compose` 使用同样参数但不指定 `--disk`，另外指定
`--card-bytes <目标卡实际字节数>`，只生成恢复镜像；实际字节数从 `disks` 查询，不使用卡面标称容量。
镜像及软件摘要来自可信清单；已准备镜像的 `images/image.json` 和工具包 `firmware.json` 可供菜单自动读取。
`auto-flash` 默认快速写入；需要完整清空时显式加 `--full-erase`，会覆盖全卡并全量检查零值，耗时较长。

快速写入会覆盖系统镜像范围，镜像之外可能残留旧数据，不能当作完整数据销毁。
即使整卡覆盖，也不能证明SD控制器隐藏块、坏块或磨损均衡区已清除。

## 自动恢复实现和故障处理

沿用官方 FAT32 CONFIG 分区的 `hobot_config.sh` 启动入口，保留原引导内容、磁盘标识和系统分区起点。
配置、约111MB完整固件包和Python恢复程序全部随镜像写入；Windows/macOS不需要挂载ext4。
启动程序注册独立 `openaria-firstboot.service`，等待 `hobot-resizefs.service` 完成后执行，安装日志
位于 `/var/lib/openaria-factory/firstboot/install.log`。CONFIG分区的 `openaria/status.json` 提供不含秘密的阶段/失败状态。

- 设备身份不符、包摘要不符或配置认证失败：在恢复配置前停止，不重启，不覆盖已有产品数据。
- 新设备已有录制软件/状态：拒绝接管。只有本工具已登记且配置包一致的恢复事务可继续。
- 断电或安装失败：保留配置备份和安装日志；重新开机尝试继续相同事务。安装器自身处理未完成的固件事务。
  新卡初始化格式化期间中断可在已登记事务内重新格式化；初始化完成后永久退出格式化步骤。
  已投入录制的数据区只尝试安全修复，不会自动格式化；严重损坏仍可能需要维修或重新刷卡。
- 配置写入中断：从相同已登记事务重新写入白名单配置。安装中断不重复覆盖已经完成的配置阶段。
- 成功：持久保存完成标记，删除启动分区的临时加密配置，再自动重启；后续开机不重复安装。
- 写卡出现I/O错误或中断：不能认为可启动，检查读卡器/接口后重新完整执行快速刷写和校验。

未经实机验收，不能将本地模拟的断电/重试测试视为所有掉电场景已验证。

## 独立 exFAT 录像区（2026-11-06 验收候选）

菜单5/`auto-flash` 默认使用新布局：官方 CONFIG 256 MiB、ext4 系统区16 GiB、
其余容量为 exFAT `RECORDINGS`（最多不足1 MiB对齐余量）。系统、录制软件和状态数据库在ext4；
录像区挂载 `/data`，录像路径 `/data/recordings`，Windows/macOS读卡器中对应 `RECORDINGS/recordings`。
普通升级保留旧80 GiB loop卷；转换布局必须重新刷卡，不能在原卡上直接缩系统区。

`--system-gib` 可设置16–64 GiB，必须为录像保留至少4 GiB。
生成镜像仍只写约10.4 GB官方有效载荷，分区表按目标卡实际容量生成；
不能把为大卡生成的镜像刷到更小卡，工具会在擦写前拒绝。大于目标的卡不会自动扩展额外空间，需重新生成镜像。
新布局要求支持exFAT的固件；旧包会在合成前被拒绝。`--storage legacy-loop` 可显式生成旧布局。

电脑合成前取得官方Ubuntu Jammy ARM64 `exfatprogs` 包并校验固定SHA-256，包随CONFIG分区写入；
首次开机离线安装。工具包中的 `tools/` 可预置此包，因此现场刷卡不必联网。
依赖来源：[Ubuntu exfatprogs](https://packages.ubuntu.com/jammy-updates/arm64/exfatprogs/download)。

挂载使用文件系统UUID和分区身份校验，权限通过exFAT挂载参数分配给录制用户。
每次挂载前限时执行 `fsck.exfat -p`；检查或挂载失败不阻止系统/Web启动，但禁止录制、禁止回退写系统盘。
启动时最多等待数据服务120秒，安全修复最多90秒。异常后文件系统只读时拒绝录制，不使用 `errors=panic`。
exFAT容量检查不把缺少inode表误判为容量耗尽。固件回滚须使用同样支持新布局的版本，不能回滚到旧loop专用版本。

系统仍是可写ext4，分区隔离减少录像故障对系统文件系统的影响，不能保证SD控制器故障或所有断电情况都不损坏系统。
验收需实际完成：双目长录、正常重启、录制中拔电后重启并再次录制、录像区故障时Web可访问，
以及Windows和macOS读卡导出。拔卡前先关闭设备；电脑提示格式化Linux系统区时应取消，仅打开 `RECORDINGS`。

## 配置范围和保密边界

保留Wi-Fi、NetworkManager和Netplan网络配置、静态IP/网关/DNS、hostname、machine-id、OpenAria设备身份、
按钮配置、当前相机/音频/编码/空间阈值、声音服务配置、ALSA音量，以及单独提取的网页提示音量。
不复制录像、旧状态数据库、事务历史、日志、用户目录、旧登录密码或SSH私钥。定时采集/焦距临时状态不恢复。
静态IP按配置恢复；DHCP方式保持，地址可能变化，不保证仍为原IP。

电脑备份采用密码派生的Scrypt＋AES-GCM。启动分区配置采用AES-GCM和板卡标识派生密钥，不随卡保存备份密码，
避免直接出现明文Wi-Fi配置并绑定原板子。**板卡序列号不是硬件保密密钥，这不抵御知道序列号或持有设备的攻击者。**
恢复后的Wi-Fi凭据仍由系统以root权限文件保存；普通未加密内存卡不能提供物理读取保密。备份密码丢失无法解密电脑备份。

## 兼容旧分步模式

菜单2仅全盘清空；菜单3仅刷官方系统，不带自动恢复；菜单4在干净系统联网后手动恢复软件与配置。
当前推荐菜单5。旧版 `.oar` 没有网页音量字段时自动恢复为100%；新备份保留实际音量。
